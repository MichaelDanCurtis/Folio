# Repeated table headers — 0.71 development

Select a table cell, open **Table properties**, and use **Repeat as header rows
on each page**. The setting applies to the selected rows. A mixed selection is
shown with a dash; leaving it untouched preserves every row's current setting.
Properties remain a table draft until the enclosing **Apply**. Cancel discards
the draft, and the committed change is one Undo step.

Only consecutive marked rows starting at the first row form the repeated
heading. Flags after an unmarked row remain stored, but do not extend the
heading. Editing the source heading updates its derived copies in Page preview;
copies do not add document text, source rows, saved field values or revisions.

## Implementation

- Rust imports direct `w:tblHeader`, hydrates missing legacy row flags, validates
  boolean editor values, and patches only a changed row setting. New and edited
  flags use `w:val="on"` / `"off"`. Untouched source syntax is retained, including
  namespace aliases and unknown attributes. Tolerant import also reads older
  boolean spellings; this is not a claim that those spellings pass the schema.
- Unchanged cell grid-span and vertical-merge properties are retained when
  changing a row setting, including omitted-default syntax and extension data.
- Pagination measures the full consecutive heading at each continuation's
  width. It accounts for that height before placing body rows. The first
  heading stays with a following complete body row group when those rows fit.
  Header-only tables and oversized groups make progress without endless pages.
- Headings preserve merged cells, fill and rich content. Derived page fields
  use the continuation's page number and final page count. Balancing replays
  derived headings without duplicating the original source rows.

invalid edits without partial writes, rich native headings, page fields,
legacy hydration, save/reopen, Undo/Redo and unrelated package parts. The
layout tests cover consecutive/missing prefixes, merged headings, fields,
orphan prevention, oversized rows, balanced columns and unequal RTL columns.
Dialog and real-bridge application tests cover mixed state, Cancel, Apply,

Open requirements:

1. Word layout comparison, including row splitting and minimum/exact heights.
   The 0.72 row-height/clipping implementation and its separate
   qualification limits are recorded in [TABLE_ROW_HEIGHTS.md](TABLE_ROW_HEIGHTS.md).
2. Manual page/column breaks inside table cells. Page preview reports that it
   does not yet position them; Word's manual-break exception is not implemented.
3. Headers spanning an unmarked merged body row. Preview reports the boundary
   conflict and omits repetition until the complete merged group is marked.
4. Headers too tall to fit with a body row group. The current continuation may
   omit the heading and reports the limitation; Word comparison is outstanding.
5. Repetition across columns and column-balancing edge cases need direct Word
   qualification. Current pagination repeats at each new flow column.
6. Tracked row/table-format authoring, row-insertion heading inheritance, nested
   repeating tables, table styles and accessible native control qualification.
